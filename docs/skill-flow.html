Skill dựng thiết kế như thế nào

Design Hagent · skill 2.16 · cập nhật 24/11/2026 · bấm vào một bước để xem agent làm gì bên trong · Thuật ngữ

Thuật ngữ

File

Base (tier 1)
File dùng chung "Design System Base". Part, token và rule trơn mà mọi app dùng. Font Inter và màu trong đó chỉ là tạm.
File app (tier 2)
Mỗi app một file Figma, ví dụ the trial app hay the first app. Dùng base làm library và giữ giao diện, rule riêng của app.
Tier 2 Template
File app sạch, bạn duplicate để bắt đầu app mới. Có sẵn trang agent, block, text style và 15 starter wrap.
Trang agent
Các trang viết cho agent đọc: AGENT RULES, AGENT PROGRESS, AGENT ROADMAP trong base; AGENT RULES (PROJECT), AGENT BRIEF và AGENT SITEMAP trong file app.
Spec block
Khối text trên trang agent, agent tìm theo tên và đọc từng phần. RULES, FLOWS, MAPPING và CHANGELOG là spec block.
Ngôn ngữ
Cái agent đọc và viết (skill, mọi block agent, tên layer và component, prompt ảnh) bằng tiếng Anh. Cái chỉ team đọc (ghi chú trên canvas, báo cáo review, trang này) bằng tiếng Việt. Copy trên màn hình theo ngôn ngữ của app.

Block agent đọc

RULES
Các rule đã duyệt của một file. Đọc hết mỗi phiên. Có bảng "What to read, and when" cho biết task cần đọc thêm block nào.
HANDOFF
Ghi chú ngắn trong block PROGRESS của base: phiên trước làm gì, phiên sau cần làm gì. Giúp phiên mới bắt đầu mà không cần ngữ cảnh.
BRIEF và SITEMAP
Mục tiêu, người dùng và tính năng của app (BRIEF), và cây đánh số mọi màn hình, trạng thái (SITEMAP).
MAPPING
Bảng các part của app: mỗi part dùng part base nào, và là wrap, fork hay local part.
CHANGELOG
Nhật ký thay đổi theo ngày. Agent chỉ đọc vài dòng đầu và thêm một dòng cho mỗi thay đổi.
FINDINGS
Chỗ thiếu của base mà app gặp phải, ví dụ thiếu part hay màu mà wrap không đổi được. Mỗi mục là một T item.
SKILL FINDINGS
Bài học về cách agent làm việc, ví dụ một lần bạn sửa hay một lỗi lặp lại. Mỗi mục là một SF item. Chỉ bạn duyệt.

Làm việc cùng nhau

Lock
Một dòng trong block LOCKS của base cho biết phiên nào đang sửa part base nào. Biển "đừng đụng, tôi đang làm" cho base.
Claim
Biển tương tự trong file app: một dòng trong mục Claims của block RULES. Ghi phiên, phần nó giữ (trang, flow, part) và ngày. Xóa khi phiên kết thúc.
Stamp ("Built on")
Dòng trên block RULES của app ghi phiên bản rule base và phiên bản skill mà app được kiểm tra gần nhất. Agent so sánh nó đầu mỗi phiên.
OK của bạn
Sự đồng ý rõ ràng của bạn trong chat. "Trông ổn" không tính. Cần cho mọi thay đổi rule, token, component, và cuối mỗi giai đoạn app mới.
OK sửa rules
Một OK riêng để sửa chính các trang rules, ví dụ thêm block. OK dựng màn hình không tính là OK này.

Part

Token / variable
Giá trị có tên (màu, khoảng cách, bo góc, kích thước) lưu trong Figma variables. Màn hình dùng token, không dùng số thô.
Wrap
Part của app chứa một part base bên trong và đổi style bằng màu, text style của app. Đặt tên kiểu the trial app/Button. Cách mặc định để tạo part cho app.
Fork
Bản sao part base trong app với cấu trúc đã đổi. Chỉ dùng khi wrap không làm được, có ghi lý do.
Local part
Part của app không có part base tương ứng. Ghi lại làm ứng viên thêm vào base sau.
Full set
Wrap có đủ mọi variant của part base (size, state, style), không chỉ những cái màn hình đang dùng.
Starter wrap
15 wrap có sẵn trong Tier 2 Template, như Button, Header, ListItem. App mới đổi tên và đổi style chúng.

Kiểm tra

Text level
Mức chữ một app cho phép trên màn hình (base rule 7.13): Silent, Minimal (mặc định) hoặc Guided cho màn cần quyết định như xin quyền, paywall. Mỗi app đặt trong Settings của RULES.
Batch
Một đơn vị việc: một flow, một nhóm part hoặc một rule áp lại. Done check chạy sau mỗi batch.
Done check script
Script lưu trong base, đếm lỗi rule trên cả file: màu chưa bind, khoảng cách thô, thiếu text style, part bị detach và hơn nữa.
Quét áp lại
Sau một rule hay pattern mới, agent tìm khắp file những chỗ làm cùng việc và áp rule ở mọi nơi, không chỉ màn hình mới.
Màu fallback
Màu thô Figma lưu phía sau một color variable. Màu sai vẫn trông đúng trong ảnh chụp, nên số đếm luôn đi trước ảnh chụp.
